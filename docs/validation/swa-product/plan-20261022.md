## 里程碑 A：CLI 独立验收

1. 全程不启动 GUI，从安装后的产品命令完成发现、合法授权、controller、Run 和根 Task。所有后继 ID 来自实际回执，保留 project/run/task/dispatch/session/request 映射。
2. 同一产品任务创建 N 个不同 child Task、Dispatch、原生 session 和所属资源。N 份真实模型执行区间存在公共重叠，重叠区间内各有真实流事件；进程存在、排队或人为等待不能满足条件。若未形成重叠，保留真实结果，不自动重新发起调用。
3. 在目标仍真实运行时指定停止一个 Worker，核停止回执、原生状态及完整所属树退出。其余至少 N−1 个 Worker 保持原 session、创建身份及 operation/fence 继续输出，其中一个接受合法追加输入并在同一会话完成。停止项保留 stopped/cancelled 及不完整成果。
4. 使用正常中文和实际跨分块边界的公开输入并发提交。核原 request、receipt、队列、operation 和自产用户正文的逐项归属。不能从最终回答看似合理推断输入没有交错。
5. 同 request、同正文回放至多执行一次；改变实际正文或选择应拒绝。只中断本项所属传输，命中真实效果丢失边界后只查询原 request；未命中记 `INCONCLUSIVE`，不换键重发，不产生虚构回执。
6. 对真实未授权、过期和跨项目范围验证拒绝，并核没有额外原生执行或错误持久副作用。未知效果保留原请求和占用，不切换模型或重建 Worker。
7. `task result` 的每份消息和文件逐项定位真实 Task/session/Dispatch 来源、完整性、读取一致性和 12MiB 边界。受限 ToolsOff 输入不当作文件写入能力。根 Task 成功条件在执行前确定，计划停止项不改写为成功。
8. 重复 stop/release、恢复及故障只针对本项明确所属资源。完整树退出按当前平台合同证明，原账号、原 Orca 和非所属进程保全。原 T11 人工接管待定范围保持独立，不用 Agent 输入冒充本人行为。

## 里程碑 B：组合候选与跨入口

在同一组合候选重新执行上述 N Worker 场景。CLI 创建的任务在 GUI 中呈现同一真实身份和全部 Worker；GUI 指定停止或追加已批准输入后，由 CLI 核原 Dispatch 状态与成果。GUI 创建的任务能够由 CLI 查询和等待，不产生第二份任务记录。

验证刷新、断线重连、未知状态、部分失败和审批提示。关闭附着页面不擅自关闭 CLI 服务；服务由其实际 owner 正常结束。静态前端、HTTP 200 或前端乐观状态不证明执行通过。

## 当前可执行检查与停止条件

`preflight.mjs` 不执行模型。在实际 Linux 上无参数和 `--workers 4` 应退出3并保留 `NOT_RUN`；`--workers 2`、非整数或未知参数应退出2，避免把不符合本轮验收规模的运行当作成功。指定非法绝对路径时只报告固定诊断，不回显误传的凭据。`git diff --check` 检查本卡文档及脚本格式。

Windows 候选、实际登录、合法当前授权、真实并发、停止、后续输入、输入跨块、完整成果、权限及跨入口行为均在真实前置齐全后执行。任何授权或来源不符、效果未知、原资源保全失败均停止依赖动作，保留原请求并继续只读诊断。结果区分 `PASS`、`FAIL`、`NOT_RUN` 与 `INCONCLUSIVE`，所有报告记录准确命令、退出码、候选及实际证据路径。
