# SWA 产品主线收口与双平台验收

基线：[适配和工作台 #21](https://github.com/songconmaisaix31-design/swarm-anything/pull/21) 的 `d2757987943b189ed4698ccbdf434feb2c12788b`。Windows 与 Linux 均以同一源码构建并测试，不使用供应商账号或调用模型。正式原生安装包和模型执行有各自的验收入口。

## 主线

1. `swa-server` 提供本机项目、权限和同源工作台；`swarm` 发现本机客户端、做连接验证并管理可移植角色资产。一个已确认的项目和一个明确的执行权限才可以进入运行流程。
2. `swa` 连接现有原生执行服务。Run、Task、Dispatch、输出和释放状态由该运行服务负责；Web 观察并操作同一事实。没有配置供应商时，工作台、项目与权限仍可运行，提交能力按当前服务事实拒绝。
3. Astrocyte、Attention Mirror、Morphogenesis 的业务数据仍由各自产品或插件管理。SWA 不运行旧混合产品、不替换个人数据目录。

## 移出当前源码

- Web：旧 Mission/任务图、资料与认知、旧工作台等整段已无本产品入口；按当前 Vite 入口、有效 Web 测试和依赖闭包保留可达代码。移除只给旧图使用的 Dagre 及旧浏览器用例，保留当前 SWA 的 Graph 和键盘/权限测试。
- Go：旧 Mission 应用层及其 DAG、预算、租约等规则没有当前消费者；旧 Judgment 包不在可执行产品入口。保留角色卡领域、插件归属、项目权限、运行时、公开契约和数据库迁移。更新架构检查中的历史包条目。
- 脚本和测试：移出指向已移除旧服务的资料、媒体、旧工作台脚本及失效测试入口。现有科研实验、来源记录和历史配置仍各自保留。历史代码可从上述基线及[旧组合完整保存点](../scripts/LEGACY.md)复现，不能用当前 SWA 读取旧正式数据。

## 无账号验证

`pnpm build` 构建目标平台的三个二进制和 Web，`pnpm test:product` 使用这些真实构建产物、回环 HTTP 和测试专用 SQLite。验证静态页面及其 JS、项目登记、CSRF/撤权、客户端被动发现、无原生运行时的真实拒绝、关闭和重启持久化，确认没有 Worker 会话或 Run 关联。修复了 `pnpm start` 在未配置端口时拒绝启动的问题；保留显式设置和传统环境变量检查。

本机 Linux 已执行构建产物的上述测试与开发生命周期检查。Windows x64 交叉编译只验证编译，真实 Windows 运行与工作台交互见[同源码双平台产品检查](../.github/workflows/product-smoke.yml)。工作流在目标系统实际启动 Go 可执行文件和 Playwright；运行结果单独记录。该验收不确认已登录 Agent、正式模型调用结果或供应商会话续接。
